# Release notes — v0.1.0-alpha.2

**Ownership Radar ES — corrective pre-release.**
Fixes silent data loss in public-API pagination plus a set of
correctness, ingestion, packaging and repository-hygiene issues
found in a repository-wide audit. Still alpha; see the alpha.1
notes for scope and known limitations.

## Highlights

- **Pagination integrity.** `significant_holdings`,
  `treasury_stock_positions` and `treasury_operations` could skip
  rows when a page boundary landed mid-tie — the emitted cursor did
  not match the declared ordering. All `QueryResult` cursors now
  carry the full composite sort key, including NULL-date and
  `row_index` boundaries.
- **Versioned, bound query cursors.** `QueryResult.next_cursor` is
  now a `q2.<…>` envelope containing the composite key, a signature
  of the issuing query (method, resolved issuer, every filter) and
  the dataset version. Reuse across methods, filters or datasets
  raises `CursorDatasetMismatch` instead of silently returning
  wrong or empty pages.
- **Consistent issuer resolution.** `issuer="SAN"` (ticker, alias,
  NIF or `Issuer` object) now works identically in every query
  method — previously only `feed()` resolved it.
- **Read-only reporting.** `ingest report`/`invariants` no longer
  create a missing database or write the universe into the
  inspected dataset.
- **Installable ingestion.** The `itf2026-v1` universe seed ships
  inside the wheel, and `ingest`/`crawl` data paths are
  cwd-relative — the pipeline works from an installed package.
- **Ingestion correctness.** Retry scans respect issuer/date/surface
  scope; transient fetch failures are retryable; `crawl_run`
  inserts match the migrated schema; crawler responses are capped
  at 256 MB.
- **CLI fix.** `ownership-radar feed` no longer crashes in the
  default table format.

## Compatibility notes

- **Query cursors produced by `0.1.0a1` are intentionally
  invalidated** — their pagination keys were incorrect and could
  skip records. They now fail closed with `InvalidCursor` instead
  of continuing silently. Resume pagination from the start of the
  result set.
- **Feed cursors (`v1.<…>`) and `feed_item_id` (`v1:<…>`) are
  unchanged** — existing feed consumers keep working.
- No dataset/schema migration is required; datasets built with
  alpha.1 open and query identically.

## Verification

- 165 tests + 30 subtests pass; `ruff check .` clean.
- Wheel + sdist build; fresh install outside the checkout loads the
  packaged 60-issuer seed and runs API/CLI/feed.
- All examples run; the demo dataset rebuilds byte-identical.
- Secret/path audit clean.

## Known residual risk

No live CNMV crawl was run for this release; network transport is
exercised through fakes/tests only. `0.1.0a2` remains alpha — the
public contract is tested but may still change before 1.0, always
recorded in CHANGELOG.md.
